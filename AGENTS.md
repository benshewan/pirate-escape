# AGENTS.md — pirate-escape

2D vertical-scrolling platformer in **Bevy 0.20**; primary target wasm/browser.
Plans live in `docs/plans/` (see `docs/plans/README.md`).

## Toolchain

`cargo`, `rustc`, `trunk` and `wasm-opt` are **not** on PATH — they come from
`devenv.nix`.

```sh
nix develop --impure                    # interactive shell
nix develop --impure -c cargo check     # one-shot
```

`--impure` is **required** (devenv reads `$PWD` via `builtins.getEnv`, empty under
pure eval; otherwise: "devenv was not able to determine the current directory").
The `devenv` binary isn't installed, so `.envrc`/direnv currently does nothing.
Nix warns about untrusted flake cache settings — harmless, or pass
`--accept-flake-config`.

## Fast rebuilds

Native (not wasm) is the iteration loop. Warm = edit `src/main.rs`, then rebuild:

| command | warm |
| --- | --- |
| `cargo check` | ~0.3 s |
| `cargo dev` (dylib) | ~0.9 s |
| `cargo run` (static) | ~3.3 s |

- **Check while editing, run to play.** `cargo check` is ~0.3 s warm.
- **Use `cargo dev` for the play loop.** It enables `bevy/dynamic_linking` (the
  `dev` feature in `Cargo.toml` + `[alias] dev` in `.cargo/config.toml`) — ~3.7×
  faster relinks. `dev-static` / `cargo run` is the static fallback.
- **Iterate natively; treat wasm as verification.** Switching to wasm means a full
  rebuild.
- **Avoid forcing a cold rebuild.** Changing `[profile.*]` in `Cargo.toml`,
  toggling `--features dev`, switching target dirs or `cargo clean` all trigger one.
  Cold `cargo check` is ~150 s (proc-macro/build-script codegen dominates); warm is
  ~0.3 s, and cold `cargo build` is ~8m45s either way.

## Scripts (inside the shell)

| Script | Runs | Purpose |
| --- | --- | --- |
| `dev` | `cargo dev` | Native, Bevy as a dylib (fast relinks). |
| `dev-static` | `cargo run` | Native, static (fallback). |
| `web` | `trunk serve` | Browser dev server + hot reload. |
| `web-build` | `trunk build --release --cargo-profile wasm-release` | Production bundle → `./dist`. |

## Gotchas

- **Trunk has no `--profile`.** Use `--cargo-profile wasm-release` (as `web-build`
  does); `--release` is still needed for Trunk's release pipeline and wasm-opt. Do
  not set `cargo-profile` in `Trunk.toml` — it applies to `trunk serve` too and
  would slow dev wasm builds.
- **Never set `TRUNK_TOOLS_WASM_OPT`.** Trunk reads it as the download *version*,
  not a path, so a Nix store path breaks releases ("failed downloading release
  archive"). `wasm-opt` comes from `binaryen` on PATH.
- **The `dev` feature is `bevy/dynamic_linking` — native only**, never for
  wasm/release/ship. The binary needs `libbevy_dylib-<hash>.so` from
  `target/debug/deps`: `cargo run`/`cargo dev` set `LD_LIBRARY_PATH`, running the
  binary by hand does not.
- **Cargo profile override precedence** is `package.<name>` > `package."*"` >
  `build-override` > `[profile.dev]`, resolved per field. With `package."*" opt-level
  = 3` set, `build-override opt-level = 0` does nothing (only its `debug = false`
  applies).
- `.cargo/config.toml` sets `getrandom_backend="wasm_js"` for wasm32; without it
  `rand`/getrandom-based crates fail to build.
- `bevy` is built with `default-features = false, features = ["2d","ui","audio"]`;
  any other subsystem must be enabled explicitly.
- `.pre-commit-config.yaml` is generated by devenv and gitignored — do not commit it.
